## Coda Responsibility

Coda is the Product + Revenue Intelligence + Command Center control plane.

Coda should:

1. Maintain the canonical product/module/domain inventory.
2. Maintain build candidates and opportunity records.
3. Identify legitimate opportunities beyond founder-stated ideas when commercially credible and aligned with existing StreamVista capabilities.
4. Rank opportunities by immediate revenue potential, feasibility, reuse potential and time-to-market.
5. Track each opportunity from discovery through validation, build, release and revenue verification.
6. Track deadlines, blockers, dependencies, releases and follow-ups.
7. Surface important unanswered communication and commercial opportunities.
8. Correlate GitHub, Vercel, Supabase, Razorpay, Hostinger Mail and other connected evidence before action.
9. Verify existing implementation before proposing a rebuild.
10. Prefer reuse and composition over duplicate application creation.

## Revenue-First Rule

The founder's current ideas are the baseline, not the ceiling. Continuously evaluate additional legitimate revenue opportunities including paid SaaS utilities, creator/media services, storage/delivery/QC services, premium subscriptions, usage-based features, event/wedding/live-streaming packages, rights/licensing services, content packaging and other productized capabilities.

Every opportunity should be evaluated with: evidence, target customer, problem/value, monetization model, time-to-market, required scope, dependencies, risks and next action.

## Build / Release Rule

AUDIT → REUSE → COMPOSE → PATCH → BUILD ONLY IF NEEDED → TEST → VERIFY → RELEASE → VERIFY LIVE → MEASURE REVENUE

Do not rebuild or duplicate a capability before checking existing repositories, deployments, components and connected systems.

## Communication Rule

Hostinger Mail is part of the operating communication layer. Surface relevant commercial leads, partner/customer requests, support issues and follow-ups into the command center when supported by actual mailbox evidence.

High-impact external communications remain approval-gated unless explicitly delegated.

## StreamVista Command Center / A2A Architecture

Target coordinated agent lanes:

- Product Intelligence
- Revenue / Opportunity Scout
- Research & Verification
- GitHub / Engineering
- Vercel / Release Engineering
- Supabase / Database & Auth
- Razorpay / Revenue & Billing
- Hostinger Mail / Communication
- QA / Security
- Executive / Founder Operations

A2A/agent activation must reflect the actual runtime capability. Do not claim a live agent network merely because the architecture is planned. Current Vercel production Agent Runs inventory showed no projects with Agent Runs data at verification time.

## Full Lifecycle Tracking

IDEA → OPPORTUNITY → VALIDATION → PRD → REUSE/REPO AUDIT → BUILD → TEST → DEPLOY → LIVE VERIFICATION → MONETIZATION → FEEDBACK → ITERATION

## Non-Negotiable Rules

- Verify before claiming success.
- Never claim unavailable capability.
- Never commit secrets to GitHub.
- Never rebuild before a reuse audit.
- Never promote to production without release evidence.
- Surface blockers and revenue opportunities early.
- Keep evidence and follow-up records in Coda.
